# 光遇国服 · 每日资讯

纯网页 App（单文件、可离线）。真实数据由脚本聚合，每天自动更新。

---

## 一、数据怎么更新？

### 方式 A：常驻守护（最推荐 —— 过了 0 点真的会自己换）

```bash
nohup python3.11 scripts/autopilot.py &
```

它是这套东西的核心，逻辑是：

1. **跨到 00:00 → 立刻抓一轮**（游戏侧任务已经刷新了）
2. **还没拿到今天的 → 每 10 分钟重试**，直到拿到为止（站方可能拖到早上才发）
3. **已经是今天的 → 降到 30 分钟一次巡检**，用来抓站方**提前发布的次日攻略**
4. 只有内容真的变了，才重建 `index.html` 的内联数据（不写无意义的盘）

### 方式 B：定时任务（不想常驻就装这个）

```bash
bash scripts/install_cron.sh
```

它会装：`00:05 起每 20 分钟一次（直到 12:00）` + `白天每 2 小时一次` + `开机自动拉起上面的守护`。
即站方发文后，平均 **10 分钟内**页面就会换新。

卸载：
```bash
crontab -l | grep -v autopilot.py | crontab -
```

### 方式 C：手动

```bash
bash scripts/refresh.sh          # 已是最新就只做增量巡检
bash scripts/refresh.sh --force  # 强制重抓
```

输出示例：
```
[2026-10-10 01:04:37] 开始抓取每日任务……
  · fetch_data.py: 站方标题 → 攻略目标日期: 2026-10-09
  · fetch_data.py: 已写回 data.json  updatedAt=2026-10-09  抓取于=2026-10-10T01:04:37
[2026-10-10 01:04:39] 开始扫描新活动 / 新季节……
  · discover_events.py: + 新发现 [collabSeason] 珍珠季·海底星海 | 即将开始 | 2026-10-22 开启
[2026-10-10 01:04:44] 内容有更新 -> 重建 index.html 内联数据
  ✓ 已内联：30 季 / 16 活动 / 19 条每日任务攻略 / data 字段 9 个
```

### 方式 D：页面里点

页面顶部会出现提示条 + **刷新** 按钮，点了就直接重拉 json 局部重渲染，不用刷整页。

## 一·五、新活动 / 新季节会自己长出来吗？

**会。** `scripts/discover_events.py` 负责这件事：

- 扫 9game 光遇「游戏新闻」列表页，按标题关键词（联动 / 代币 / 活动攻略 / 正式开启 / `XX季·…`）识别活动与季节资讯
- 对每篇新文章抓详情页，解析出：**发布时间、活动时间区间、代币名、地图、摘要**
- 去重后写进 `events.json`（标记 `auto:true` + 原文链接），页面卡片直接出现，弹窗里带 **「查看原文攻略（自动发现）」** 入口
- 顺带同步 `data.json`：新季节的开启日期、当前进行中的活动列表
- 自动条目 3 天内带 **「新」** 红标，过期自动消失
- 超过 45 天的旧帖不收，避免把 2024 年的陈年攻略当新闻

所以「珍珠季 10-22 开启」这类新季节消息，**不用改代码**，脚本自己会抓进来。

## 二、页面会自动判断"数据过期"吗？

会。基准就是 **00:00 —— 国服光遇的每日刷新时刻**：每日任务、季节蜡烛、大蜡烛全部在 0 点整刷新，暴风眼每周六 0 点刷新。（国际服才是下午 15:00 / 冬令时 16:00。另外**复刻先祖的回归时间是早上 6:00 开始**，那是活动时间，不是任务刷新。）

| 时刻 | 数据状态 | 页面表现 |
|---|---|---|
| 00:30 | 仍是昨天的 | 蓝色提示：**今日任务已于 00:00 刷新**，攻略一般 6:00 后才陆续发布，现在显示的仍是 X 月 X 日（属正常等待） |
| 09:00 | 仍是昨天的 | 橙色警告：**数据停留在 X 月 X 日**，今日内容尚未更新 + 刷新按钮 |
| 14:00 | 今天是今天的但抓取已超 8 小时 | 橙色警告：今日数据抓取于 8 小时前，可能已被更正 |
| 正常 | 新鲜 | 无提示条；右上角显示「刚刚 / 12 分钟前」 |

另外还有两道自动守护（退避式，不会无谓轮询）：
- 每 **60 秒**检测一次是否跨过 00:00 → 跨了就自动重拉（重拉间隔按 3 / 10 / 30 / 60 分钟退避）
- 从后台切回页面 / 窗口重新获得焦点 → 立即检查一次
- 拿到今天的数据后自动降到 30 分钟一次低频巡检

## 三、重要说明：file:// 打开的局限

直接双击 `index.html`（`file://` 协议）时，浏览器出于安全策略**禁止 `fetch` 读取本地 json**。所以：

- 页面显示的是**构建时内联进去的数据**（`scripts/build_inline.py` 烘焙进 HTML）
- **配图同样已内联**：本地攻略图（`assets/*.jpg`）在构建时被压成 base64 直接写进 HTML，
  所以即便只带走 `index.html` 一个文件、不带 `assets/` 目录，图片也能正常显示
- 即使有网也拉不到新数据，提示条会写明「本地直接打开不会自动更新，需重新运行更新脚本」
- 想让它能实时刷新，用本地服务器打开：

```bash
cd /workspace && python3.11 -m http.server 8080
# 浏览器访问 http://127.0.0.1:8080
```

## 六、进阶：接第三方实时接口（真正 00:00 秒更）

攻略站发文慢是硬伤。**第三方接口的数据由攻略组维护，跟着游戏侧一起 00:00 刷新** —— 配了它，凌晨打开就是当天真实任务，不用等到早上。

### 要拿到什么

支持 **8 个端点**，不只是任务文字，还有**官方攻略图**：

| 端点 | 内容 | 页面在哪儿显示 |
|---|---|---|
| `gyrw` | 每日任务文字 | 今日必做（标签显示「实时接口」） |
| `scrw` | **每日任务位置图** | 今日必做卡片下方（配图） |
| `lzwz` | 大蜡烛（`dlwz`）/ 季蜡（`jlwz`）位置 | 蜡烛页大蜡烛卡片（含各图真实位置图）/ 季蜡卡片 |
| `mf/mf` | 今日免费魔法 | 工坊 & 魔法 |
| `gytq` | 红石 / 黑石天气 | 今日落石点 |
| `hdrl` | **活动日历图** | 活动页顶部 |
| `scfk` | **复刻先祖位置图** | 复刻卡片 |
| `djs` | 季节剩余倒计时 | 数据层备用 |

### 三步搞定（KEY 免费）

```bash
# 1. 打开 https://api.t1qq.com 注册（QQ / 邮箱 / 手机都行）

# 2. 登录后进 https://api.t1qq.com/user/key 复制你的 KEY

# 3. 回来保存并自检
bash scripts/set_api_key.sh 你的KEY
python3.11 scripts/check_api.py
```

看到 `✓ 已写入 data.json：` 就成功了，接着重建页面：

```bash
python3.11 scripts/build_inline.py
```

### 出错怎么办

```bash
python3.11 scripts/check_api.py --dump    # 打印每个端点原始返回
```

把这段 JSON 贴给我，我据此精调解析规则（模块已做**宽容解析**，字段名叫 `rw` / `data` / `list` 都能接住，但各家结构确实可能不同）。

### 会不会因为第三方挂了就废掉？

不会，链路设计是**自动降级**的：

```
有 KEY  →  第三方接口（秒级、带配图）
   ↓ 失败 / 没解析出内容 / 网络超时
9game 文章抓取（小时级、文字为主）
   ↓ 再失败
保留上一份数据 + 页面顶部如实提示
```

我用一个无效 KEY 实测过：`请求密钥KEY不正确 → 回落到文章抓取 → 数据正常写回`，全程无报错、无中断。

### 隐私

KEY 只存在本机 `config/api.env`（权限 600），不会内联进 `index.html`，也就不会随页面分享出去。
但既然这个文件在你的仓库目录里，**别把 `config/` 提交到公开仓库。**

### 图片（任务位置图 / 活动日历 / 复刻图）怎么处理

三个图片端点（`scrw` / `hdrl` / `scfk`）**直接返回 JPEG 二进制**，不是 JSON。所以：

- 抓取脚本把它们下载到本机 `assets/`（如 `assets/taskpic.jpg`）；
- `build_inline.py` 构建时把 `assets/` 图**压缩为 base64 内联进 `index.html`**（映射表 `INLINE_ASSETS`），
  前端 `apiImg()` 优先使用内联副本 → 单文件、离线、脱离 `assets/` 目录都不裂图；
  `data.json` 仍保留轻量路径（`assets/taskpic.jpg`），所以文件本身不会变大；
- **KEY 只出现在服务端请求里，绝不进页面**，图片同理不会泄露 KEY；
- `lzwz` 会**区分两类蜡烛**：`dlwz`=大蜡烛、`jlwz`=季蜡，二者不可混用。
  大蜡烛地图形如 `["云野3","雨林2","暮土2"]`，其中**数字是当日该地图的「情形编号」(1-3)，不是数量**；
  **每个有大蜡烛的地图固定刷新 4 处**（国服按下表轮换：周一霞谷 / 周二暮土 / 周三禁阁 / 周四云野 /
  周五云野+雨林+霞谷 / 周六云野+雨林+暮土 / 周日雨林+暮土+禁阁）。
  大蜡位置图（`dl` 目录下的 CDN 直链，不含 KEY）会下载到本地 `assets/` 一并内联；
- 季蜡位置图同样来自 `lzwz`（`jl` 目录）的 CDN 链接，仅在**季节进行期间**展示（空窗期不显示，避免误导）；
- 下载失败（如触发接口配额）会跳过该图，**不影响文字数据**，页面用友好提示兜底。

### 接口配额

免费 KEY 有每日调用额度（实测约在每天 08:00 重置）。守护进程只在「跨 0 点 / 还没拿到当天数据」时密集请求，平时低频巡检，不会无谓消耗。
若某次刷新恰好撞上额度上限：文字数据仍会更新（9game 兜底），只是当天配图可能暂时缺，等下次刷新自动补上。

## 七、界面功能（本次新增）

### 1. 深色模式
右上角「☀ / 🌙」按钮一键切换，选择存入 `localStorage`；首次访问**跟随系统**深色偏好。
主题在 `<head>` 内联脚本里预设，避免刷新时闪白（FOUC）。

### 2. 一键生成「今日任务」分享图
今日页顶部「生成今日任务分享图」按钮 → 用 Canvas 合成一张竖版卡片（日期 + 4 条任务 + 来源 + 数据日期），
弹窗预览，可下载 PNG / 长按保存，方便直接发群里。

### 3. 攻略分步步骤
`guides.json` 每条攻略新增 `steps` 字段；点击任务卡弹窗在「地图 + 位置 + 技巧」之外，
再渲染**有序完成步骤**。今日页落石点也补上了地图标注（与大蜡烛页一致）。

### 4. 日历页（历史 + 时间轴）
底部新增第 5 个 tab「日历」：
- **时间轴**：活动 / 新季节 / 复刻 的时间段一览，进行中与即将用标签区分；
- **往日任务回顾**：`fetch_data.py` 每次落库把当天任务快照追加进 `history.json`（按日期去重、保留 90 天），
  页面以网格回看，点开查看当天完整任务。历史从启用日起逐日累积。

### 5. 复刻先祖图鉴库（攻略向）
`rebirthGuides.json` 收录国服近期 + 经典复刻先祖，每个含：
- **位置路线**：所在地图的自绘 SVG 示意 + 具体位置文字；
- **兑换树**：动作 / 斗篷 / 面具 / 发型 / 赠礼等节点，各带**参考价**与「必换 / 推荐 / 可选」优先级；
- **整组参考消耗**与**走法小贴士**。

今日页「复刻先祖 / 近期复刻」卡片凡能匹配到图鉴的先祖，会带绿色「攻略」标记，
**点击即弹出**图鉴详情（当前复刻为「查看兑换攻略」按钮）。匹配按 `data.json` 的
`ancestor`（如「圣岛季 · 放松日浴者」）去 contains 图鉴的 `name` / `season`，无需建精确映射。

> ⚠️ 兑换树价格为社区公开图鉴整理，**仅作参考，实际以游戏内复刻先祖友谊树为准**；位置与走法为固定点，准确度较高。
> 后续可继续在 `rebirthGuides.json` 里追加更多老季节先祖，改完跑 `scripts/build_inline.py` 即生效。

### 6. 季节攻略库徽标
「季节」页对即将开启的季节（如现在的珍珠季）自动加**「即将开启」**蓝色徽标，
一眼可见当前/下一季进度（依据 `data.json` 的 `season.name` 自动匹配，无需手改）。

### 7. 数据可靠性校验（多源交叉 + 合理性告警）
`scripts/validate_data.py` 在每次 `fetch_data.py` 落库后自动运行，产出 `data_status.json`，
页面据此在顶部显示**红/黄告警条**，header 有一颗健康圆点（绿=通过 / 黄=警告 / 红=错误）：

- **来源可追溯**：实时接口 / 攻略文章 / 复刻 / 新季节各记 `ok|fail|skip`；多源同挂直接报错，
  接口挂了用文章兜底会提示「可能延迟数小时」；
- **多源交叉校验**：大蜡烛地图、每日任务、免费魔法在「接口 vs 文章」结论不一致时告警；
  重点防**落石自相矛盾**（接口有实况图、文章却写「今日无落石」——曾发生过的真实误报）；
- **字段合理性**：每日任务应为 4 条、大蜡烛地图须在已知集合、落石不能既无图又无文字、
  数据超 24h 未更新、季蜡「进行中」却无位置等。

手动巡检：`python3.11 scripts/validate_data.py`（读当前 data.json 出报告）。
告警条的样式与文案见 `index.html` 的 `renderHealth()`；验证脚本：`scripts/verify_health.py`。

### 8. 每日 Web Push 推送（0 点主动通知）
「信息找人」：每天 0 点数据更新后，主动给订阅者发一条通知（大蜡烛地图 / 落石 / 免费魔法摘要）。

- **订阅**：页头 🔔 铃铛按钮 → 允许通知 → 浏览器生成 Web Push 订阅，用 anon key 直接入库
  `push_subscriptions`（RLS 仅允许 anon 插入，拿不到他人端点）；
- **发送**：Supabase Edge Function `push-send`（Deno，纯 Web Crypto 实现 RFC8291 aes128gcm + VAPID，
  无外部依赖）—— 校验 Bearer 令牌后读订阅、加密投递，**VAPID 私钥与订阅密钥不离开 Supabase**；
- **触发**：GitHub Actions 每日 0 点 `fetch+build` 后跑 `scripts/push_notify.py` 组摘要并调 `push-send`。

> 基础设施已全部上线并验证（Edge Function 鉴权/响应、anon 插入 RLS、Actions 触发返回
> `{sent,failed,total}`、线上 SW 注册 + push 事件处理器）。**真机通知投递**需你在手机浏览器
> 点 🔔 订阅后实测（沙箱无头浏览器无法完整模拟 FCM/APNs 投递）。订阅后可让我手动触发一次测试推送。

落点：Supabase 项目 `xiangsuZZ`（ref `mdkvbklgkmwtfscderrc`），表/函数均 `push_` 前缀，与现有 `chats`/`personas` 隔离。
